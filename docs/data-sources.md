# Источники данных и стратегия парсинга

## Что нам нужно от источника

- сеть;
- город или магазин;
- период действия акции;
- название товара;
- старая и новая цена;
- валюта;
- ссылка на источник;
- изображение товара, если доступно.

## Приоритетный список сетей для MVP

### Kaufland

Похоже на хороший кандидат для первой интеграции:

- есть публичная страница летаков;
- сеть широко покрывает Чехию;
- обычно есть структурированные промо-страницы или каталоги.

Стратегия:

- сначала искать JSON/HTML данные, которые подгружает сайт;
- если нет, брать HTML карточки;
- если только PDF, парсить PDF как fallback.

### PENNY

Тоже подходит для первой волны:

- часто публикует еженедельные акционные материалы;
- вероятен HTML или PDF формат.

Стратегия:

- сначала HTML/JSON;
- затем PDF fallback;
- store locator использовать отдельно для сопоставления города.

## Связь с дайджестом

Сводка в Telegram не парсит сайты сама: она читает уже сохранённые записи и при необходимости дёргает ingestion через слой [`offers.ts`](../supabase/functions/_shared/offers.ts) (`preferStored` + `allowLive`). Как из этого строится текст и где дедупликация, см. [digest-pipeline.md](digest-pipeline.md).

## Нормализация offers

Каждая акция в БД должна иметь единый формат:

- `chain_code`
- `city_slug`
- `store_external_id`
- `title`
- `brand`
- `category`
- `price_current`
- `price_original`
- `discount_percent`
- `valid_from`
- `valid_to`
- `source_url`
- `source_type`
- `raw_payload`

## Как связать акции с городом

Есть 3 возможных сценария:

### 1. Акция общая по сети

Показываем всем подписчикам этой сети в Чехии, если сеть представлена в их городе.

### 2. Акция по магазину

Показываем только пользователям, у которых выбран город, связанный с этим магазином.

### 3. Источник не дает точный магазин

Используем мягкую привязку:

- если летак региональный, связываем с регионом;
- если только общесетевой, помечаем `scope = national`.

## Защита от ломкости

- у каждой сети отдельный adapter;
- raw-ответ сохраняется в БД для отладки;
- при ошибке одного adapter остальные продолжают работать;
- в digest не включаем неподтвержденные записи без цены или периода.
