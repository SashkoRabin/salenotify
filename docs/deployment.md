# Deployment plan

## Рекомендуемый базовый контур

- `Supabase`:
  - Postgres
  - Edge Functions
  - Cron
- `Telegram Bot API`:
  - webhook на `telegram-webhook`

## Почему это подходит под бесплатный MVP

- нет необходимости держать постоянно живой backend;
- Telegram webhook вызывает функцию только при событиях;
- ежедневная рассылка запускается по расписанию;
- БД и функции находятся в одной платформе.

## Последовательность запуска

1. Создать бота через `@BotFather`.
2. Создать проект в Supabase.
3. Задать secrets из `.env.example`.
4. Применить миграцию `0001_init.sql`.
5. Задеплоить функции:
   - `telegram-webhook`
   - `daily-digest`
   - `ingest-source`
6. Установить webhook через `setWebhook`.
7. Настроить cron на `daily-digest`.

## Что важно учесть

- webhook URL должен быть публичным `https`;
- секрет Telegram webhook нужно проверять на каждом запросе;
- парсеры по сетям должны быть идемпотентны;
- digest не должен дублировать уже отправленные результаты.

## Когда понадобится усиление

Если:

- вырастет число пользователей;
- появится тяжелый PDF parsing;
- часть сетей будет отдавать очень тяжелые страницы;

тогда ingestion лучше вынести в отдельный worker, например на Python.
